How it works

Designed to be inspected.

A working prototype. Boundaries included.

  1. 01
    ReadModel

    Copies every value, and cites the line it came from.

  2. 02
    VerifyCode

    Opens each cited line. A value that isn’t there is refused.

  3. 03
    JudgeCode

    Uses the revision in force that day. Unclear always means no.

  4. 04
    InvestigateAgent

    Reads what each problem needs. Explains. Changes nothing.

  5. 05
    ProposeModel

    Holds, or proposes release. A second reader checks it.

  6. 06
    DecideYou

    Release waits for your name, then checks everything again.

  7. Acceptance lab

    Scores every run against labels written before the first one. Never imports the desk.

Six steps.
Four hands.
One signature.

Each part does one thing well.

The model reads, because reading is what it’s good at. Code checks, because arithmetic shouldn’t be a matter of opinion. The agent investigates, because every problem needs different evidence. And you decide, because a release can’t be called back.

When anything is unclear, the lot is held. Holding is cheap. Releasing waits for you.

    Run it yourself

    Yours to run.

    git clone https://github.com/Moezusb/release-desk.git && cd release-desk python3.13 -m venv .venv && source .venv/bin/activate pip install -e ".[dev]" release-desk serve --offline # the workspace at http://127.0.0.1:8930 release-desk eval --offline --repeat 3 # correctness first, then agreement python -m acceptance_lab evaluate eval/results-offline.json python -m acceptance_lab check-mapping pytest # 35 tests, all offline

    Offline, it’s free. Live runs use your own Anthropic credentials, or the GitHub workflow with identity federation. No key ever touches the browser or the repository.

    Questions worth asking

    Four questions, answered in the open.

    Can the mapping be trusted?

    ↗

    Six vendor mappings, checked against the source dictionary, the canonical fields and the documents themselves. Meaning, units, dates, joins, and every last lot.

    How do you accept output that varies?

    ↗

    Score every run against answers written in advance. Correctness first, agreement second. Then plant failures, and make sure they’re caught.

    What stops a confident wrong answer?

    ↗

    Every value cites its line, and code checks it’s really there, on the right row. When anything is unclear, the lot is held. See LC-24034.

    Where is it an agent, and where a workflow?

    ↗

    Reading, checking and proposing run on rails. Investigating doesn’t: the agent decides what to read next. Compare LC-24033 with LC-24037.

    Every document, person, product and company here is invented. Built on Continuum, an open-source agent framework. Designed to be inspected, not taken on trust.
